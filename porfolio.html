Projects

Two systems I built end to end — a real-time messaging server and a network traffic analyzer, each solving a distinct technical problem.

Real-Time Chat Application

A multi-user real-time chat application built on a Python WebSockets server with a lightweight browser-based client — designed around a proper client-server architecture rather than request/response polling.

Client connects WebSocket server Broadcast queue Live message feed
Python WebSockets JavaScript HTML CSS

The problem

Most learning-project chat demos fake concurrency. This needed to genuinely hold many simultaneous connections and broadcast messages without one slow client blocking the rest.

Technical highlights

  • Client-server architecture with a persistent WebSocket channel per user
  • Concurrent connection handling for multiple simultaneous users
  • Real-time message broadcasting to all connected clients
  • Clean disconnect handling to prevent dangling sockets
  • Lightweight browser-based interface with no external framework overhead

Network Traffic Analyzer

A Python-based network traffic analyzer that captures and inspects TCP, UDP, and ICMP packets, then applies rule-based analysis across protocol, port, and frequency patterns to surface suspicious traffic.

Packet capture Protocol parsing Rule-based analysis Visual traffic report
Python Scapy Pandas Matplotlib

The problem

Raw packet captures are unreadable at scale. The goal was to turn a live capture into readable signal — which flows look normal, and which look worth a second look.

Technical highlights

  • Live packet capture across TCP, UDP, and ICMP
  • Protocol and port-level analysis of captured traffic
  • Packet-frequency analysis to flag abnormal volume
  • Rule-based traffic-pattern detection for suspicious flows
  • Visualized traffic summaries with Matplotlib
